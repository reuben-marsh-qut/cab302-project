# goals
isComplete should be a generated column "GENERATED ALWAYS AS (progress>=completionThreshold)" 

the meaning of completionThreshold depends on completionType, for binary goals (where completion is YES/NO) it is just 1 or 0, for progressive goals (where a numerical goal is progressed towards overtime (ie $10k saved)) is is the progress towards the goal.


```
table goals
PK AI INT, goalId
NOT NULL INT, userId FK ON DELETE CASCADE

NOT NULL TEXT, goalTitle
NOT NULL TEXT, catagory constraint (mind, body, social, planet)?
NOT NULL INT ,startsAtUnixTime
Nullable INT dueUnixTime// if null does not expire

NOT NULL INT progress
NOT NULL INT completionThreshold
NOT NULL INT completionType (constraint 1,2,3) etc binary (yes/no), progressive (0->1m steps by eoy) 
NOT NULL INT, isComplete (constraint 0,1) use https://sqlite.org/gencol.html
```

# habits
The daily/weekly/monthly task derived from a habit is autogenerated 

```
table habits

PK AI INT, habitId
Nullable INT, goalId FK
NOT NULL INT, userId FK ON DELETE CASCADE

NOT NULL TEXT, habitTitle  // also for derived tasks
NOT NULL TEXT, catagory constraint (mind, body, social, planet)?

NOT NULL TEXT, repeatFrequencyType // constraint daily, weekly, monthly?
NOT NULL INT, repeatFrequency // 1 and daily = every day, 2 and daily = every 2 days, 2 and weekly = every 2 weeks
NOT NULL INT startsAtUnixTime // start tracking habit from this point.
Nullable INT dueUnixTime // if null does not expire IE if you wanted to go for a walk each day in November but none thereafter this would be set to expire 30th nov 11:59
NOT NULL INT completionThreshold // for derived tasks

NOT NULL INT doesContributeDirectlyToGoal CHECK(doesContributeDirectlyToGoal IN (0, 1)) (ie progress in steps would directly add steps to steps goal)

```
