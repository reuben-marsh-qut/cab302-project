# Rooted — Basic Release Plan

## Release Goal
The goal of the first release is to produce a desktop application that gives users the ability to help build postive wellbeing behaviours thorough goals, habits and activities.

The application is intented to include gamification features such as XP, levels, streaks, and rewards to attempt to encougrage users to keep using the app

The project is going to be developed through **weekly Sprints**. Each sprint is should aim to add a working part of the applciation rather then leaving all intergation until the end

The features included in each sprint is subject to change depending on team progess and feedback. 



## Release Approach

The team will work in one-week Sprints.

At the start of each Sprint, the team will select Product Backlog Items that support a clear Sprint Goal.

At the end of each Sprint, the team should aim to have a working Increment that can be demonstrated and reviewed.

The Release Plan is a forecast and may be updated as the team gets a better understanding of its development speed and the complexity of the project.



# Proposed Sprint Plan

## Sprint 1 — Application Setup and Basic Goals

### Main Goal

Create the basic application structure and allow a user to register, log in and create a wellbeing goal.

### Candidate User Stories

* US-01 — Register an Account
* US-02 — Log In
* US-05 — Browse Goal Templates
* US-06 — Create a Long-Term Goal
* US-32 — Persist My Progress

### Expected Outcome

At the end of the Sprint, the team should be able to demonstrate a user creating an account, logging in, selecting a goal and having that goal saved locally.



## Sprint 2 — Habits and Activities

### Main Goal

Allow goals to lead to habits and activities that the user can work on.

### Candidate User Stories

* US-11 — View Goal Progress
* US-15 — Generate Habits From Goals
* US-16 — Understand How a Habit Supports a Goal
* US-17 — Track Habit Completion
* US-18 — View Activities I Need to Complete

### Expected Outcome

Users should be able to see the habits and activities connected to their goal and understand what they need to complete.



## Sprint 3 — Activity Completion and XP

### Main Goal

Complete the main Rooted gameplay loop by allowing users to complete activities and earn XP.

### Candidate User Stories

* US-19 — Complete an Activity
* US-20 — Complete Standalone Activities
* US-21 — View Activity Information
* US-22 — View Completed Activities
* US-24 — Earn XP
* US-25 — Increase My Level

### Expected Outcome

Users should be able to complete activities, see their progress update and earn XP and levels.



## Sprint 4 — Streaks, Rewards and Reports

### Main Goal

Add features that help users stay motivated and understand their progress.

### Candidate User Stories

* US-26 — Build Habit Streaks
* US-27 — Earn and View Rewards
* US-28 — View Progress Over Time
* US-29 — Compare Wellbeing Categories

### Expected Outcome

Users should be able to see streaks and rewards and view their progress across Mind, Body and Social.



## Sprint 5 — Goal Management and General Improvements

### Main Goal

Improve the overall usability and completeness of the application.

### Candidate User Stories

* US-03 — Update Profile Information
* US-04 — Log Out
* US-07 — Have Multiple Active Goals
* US-08 — Edit a Goal
* US-09 — Pause and Resume a Goal
* US-10 — Delete a Goal
* US-12 — View Completed Goals
* US-30 — Navigate the Main Application
* US-31 — Use Different Window Sizes

### Expected Outcome

The main workflows of the application should be easier to use and more complete.



## Later Sprints / Stretch Features

If the team has additional time, later Sprints may include:

* US-13 — Receive Goal Recommendations
* US-14 — Reconsider an Unsuccessful Goal
* US-23 — Search and Filter Activities
* Accessibility improvements
* Notifications
* Theme customisation
* Additional testing and UI polish

These features should only be prioritised once the core application is working reliably.



# Release Priorities

The team should prioritise work in roughly this order:

1. Core application functionality
2. Goals, habits and activities
3. Data persistence
4. XP and progression
5. Reporting and rewards
6. General usability improvements
7. Optional features

Must Have features should take priority over Should Have and Could Have features.



# Release Success

The first release will be considered successful if users can:

* Register and log in.
* Create wellbeing goals.
* Work towards goals through habits and activities.
* Complete activities and have their progress saved.
* Earn XP and levels.
* Build streaks and earn rewards.
* Review their progress over time.
* Use the application reliably as a JavaFX desktop application.

The Release Plan should be reviewed throughout development and changed if the team's actual progress shows that the original plan is unrealistic.
